# Port-to-City interface fidelity ledger

The visual concept established the overall editorial structure. The shipped
route keeps that structure while removing unsupported example copy and using
only the reviewed record package.

| Comparison point | Concept | Implemented route |
|---|---|---|
| Visual source | Preliminary archive contact sheet | Ten exact tracked derivatives with canonical IDs and hashes |
| Opening | Image-led title and recipient navigation | Same hierarchy, with route-specific title, audience and hero record |
| Evidence sequence | Dense editorial grid | Four chapters with native image ratios and complete ten-record coverage |
| Evidence detail | Right-side evidence sheet | Right sheet on desktop, bottom sheet on mobile, with Radix focus management |
| Claim boundary | Example observed/reported/unresolved sections | Record-specific observed, archive-reported and unresolved content |
| Recipient cuts | One nav row | Shareable neutral, Old Port and SDC URLs over one evidence core |
| Applications | Three practical concepts | Three cut-specific activations with audience, records and production dependency |
| Provenance | Compact footer | Artifact ID, source authority, license and internal-review status |
| Mobile | Not represented in the concept | Responsive single-column chapters, horizontal chapter navigation and bottom sheet |
| 3D | Not part of the evidence architecture | Intentionally omitted because it adds no proof to the first buyer review |

Two generated concept details were deliberately rejected: unsupported scene
identifications and placeholder review dates. The application only renders
claims present in the evidence package.
