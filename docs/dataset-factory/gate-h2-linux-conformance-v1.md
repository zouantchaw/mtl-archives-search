# Gate H2 Linux Conformance v1

This packet freezes the ordered test universe for GitHub issue #101 and verifies a hash-pinned evidence bundle. It is a local contract only: it does not execute Podman, provision a host, read credentials, access Cloudflare or D1, contact a provider, or activate any stage.

`npm run gate-h2:linux-conformance-fixture-verify` verifies the tracked nonproduction fixture. A future producer may pass absolute `--bundle-root` and `--evidence-root` values. The verifier rejects unknown or duplicate flags, symlinked roots or ancestors, and evidence that cannot be retained and revalidated from a final-component no-follow descriptor.

For every retained read, the verifier snapshots every directory from the filesystem root through the retained-read root and relative parent chain before opening the leaf. Each snapshot records directory type plus exact device, inode, owner, group, mode, and link-count identity. It opens the final leaf with `O_NOFOLLOW`, then revalidates that full ancestor chain immediately after the open and again after the retained descriptor read. It separately requires the opened leaf inode/device/size to equal the pre-open leaf and rechecks the final path against that retained inode, while retaining the leaf owner, mode, link-count, and size bounds. Therefore a pathname redirected to an arbitrary external file cannot be accepted: the opened leaf must be the pre-race leaf inode and the ancestor chain must retain its exact identity across the read.

This is a before/after validation invariant, not a claim of native `openat` traversal or retained directory descriptors. A transient ancestor replacement that is restored before either revalidation is not atomically observable; the verifier rejects any observed unsafe or changed ancestor, and the leaf inode equality still prevents accepting a redirected arbitrary external leaf.

A future strict bundle must contain the exact 69-case universe, one ordered passing result per case, per-case evidence-kind/schema bindings, safe relative evidence pins, and the existing build receipt source identity: 40-hex Git `commit`, 40-hex Git `tree`, and 64-hex `source_manifest_sha256`. It must also bind matched builder and admitted OCI `name@sha256:` references and digest fields, a hash-and-byte-pinned rootless Podman executable, Linux kernel/architecture, and producer/run identity. Strict mode still ends in an explicit `H2_LINUX_CONFORMANCE_STRICT_SEMANTICS` rejection in packet 1 because individual case semantic validators do not exist yet. A later packet must add those validators before strict admission can become possible. This verifier is an approval boundary, not admission: paid Linux execution, D1 chronology writes and reads, provider requests, and activation require separately approved packets.
