# Gate H2 Builder Packet 3C Local Machinery v1

Packet 3C replaces the Packet 3B deliberate stop with local executables for the next reviewable boundary of Issue #101. It provides no final upstream pin, x86 Linux build, host attestation, D1 mutation, production authority, or deployment.

## Acquisition

`crates/gate-h2-broker/scripts/acquire-builder-inputs.mjs` validates the raw lock before any request. It uses only lock-declared HTTPS URLs and digest-pinned OCI locators. HTTPS is TLS-only, redirects are refused, requests carry no user authorization or ambient credential material, and proxy/netrc/TLS override environment is cleared. OCI selection is explicit: manifest artifacts use Registry V2 `/manifests/sha256:<digest>` while config and layer/blob artifacts use `/blobs/sha256:<digest>`. A public OCI 401 may be followed exactly once through an anonymous Bearer flow: one strict challenge, an approved HTTPS realm, exact service and `repository:<locked-repository>:pull` scope, a token request containing only service and scope, and one memory-only Bearer retry. Docker Hub is bound to `auth.docker.io` with service `registry.docker.io`; other authorities may use only their own HTTPS realm. Basic auth, user credentials, cross-authority/unapproved realms, extra scopes, redirects, malformed/duplicate fields, and a second 401 fail closed.

Downloads are sequential and bounded by the Packet 3B artifact/aggregate limits, with timeout, identity content encoding, exact content-length when supplied, exact byte count, and exact SHA-256 checks before publication. Files are created through an exclusive temporary file, fsynced, sealed to `0444`, and published without replacement. The destination is an owned `0755` tree with safe relative members. Linux reruns the descriptor-anchored acquired-tree verifier before success and reports a byte-only boundary on macOS. Failed acquisitions roll back files and newly created nested directories, preserving the primary failure while attaching cleanup errors. The exported transport function is the only test seam; the production CLI uses the native TLS fetch path and has no fixture mode.

## Offline Materialization

`materialize-builder-offline.mjs` sanitizes its environment, verifies the exact raw lock, acquired tree, and trusted materializer commit/tree join, and derives every runtime mapping from acquired bytes through the Packet 3B derivation helper. It supports only the already-closed TAR, gzip, and whole-file vocabulary. It does not perform network access, subprocess lookup, package resolution, timestamp capture, host metadata capture, or OCI overlay/package installation.

The materializer creates a temporary exact `0755` runtime tree, emits the canonical runtime manifest, and creates a deterministic canonical `rootfs.tar`. It then emits exactly six exclusive `0444` output files: `runtime-manifest.json`, `rootfs.tar`, `layer.tar`, `config.json`, `manifest.json`, and `index.json`. `layer.tar` is byte-identical to `rootfs.tar`; the config diff ID, manifest descriptors, index platform descriptor, and final digest reference are all derived from those bytes. The lock's explicit `runtime_contract.output_image_repository` keeps the produced builder namespace separate from any source base-image namespace. The receipt is a canonical `0444` file at an explicit path outside the six-file output directory, and a pre-existing receipt is always rejected. Output, receipt, and temporary parents are owner-only enough for the race model. Every failure cleans files created by this invocation, fsyncs cleanup directories, and preserves the primary error if cleanup also fails. Success means the full existing receipt verifier has re-read and admitted the lock, acquired tree, output graph, and receipt.

## Comparison

`compare-builder-receipts.mjs` independently verifies each receipt/output/acquired bundle against the same raw lock and trusted materializer context. It requires exact equality of all six output identities and final image reference; a changed output, receipt graph, or lock binding fails. It reports the two materializer records separately. The byte comparator deliberately reports `byte_reproducible_pending_host_independence`: caller-provided producer labels are not treated as proof of independent producers, and signed host/run envelopes remain a later unsupported admission boundary.

## Verification Boundary

The focused Packet 3B/3C test uses a deterministic in-process HTTPS/OCI transport fixture, truncation/oversize/hash/redirect/auth failures, acquisition cleanup, two offline materializer runs, full receipt self-verification, stale-output rejection, and comparison. The exact Linux test runs in a network-disabled, read-only Node container. The host test remains fail-closed for full byte-tree work on non-Linux hosts. These fixtures are not the final real lock or build evidence.

The next Issue #101 packet must review real external sources, create the final immutable lock, measure the materializer closure, and run two independently attributable real x86 Linux/Podman builds. Source-policy research leaves the final project-source/config category, the native `tar_gzip` bundle, and the Cargo vendor/license artifact as subsequent supply-chain work; this packet does not invent those inputs. Host independence still requires signed native evidence; this packet must not be upgraded by relabeling synthetic producer strings.
