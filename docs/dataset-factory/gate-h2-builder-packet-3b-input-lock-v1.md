# Gate H2 Builder Packet 3B Input Lock v1

Packet 3B defines local validators and a deliberately non-materializing offline entrypoint for Issue #101. It is not build evidence, an acquisition receipt, an OCI image, or production authority.

The external-input lock records only acquired external archives and blobs. Its concrete archive sources are `oci_layer`, `rust_distribution`, `rust_musl_target`, `node_distribution`, `native_package`, and `cargo_vendor`; its concrete whole-file/blob sources are `cargo_config` and `ca_pem`. OCI manifests and configs are metadata-only and never runtime mapping sources. Every archive artifact declares the closed `archive_format` vocabulary `tar` or `tar_gzip`. XZ, ZIP, APK multi-stream packages, Zstandard streams, and every other format are unsupported by this packet; tree-overlay and package-install semantics are also unsupported. A runtime mapping never claims that `/opt/gate-h2` files were downloaded: each destination names one approved source artifact, either an exact member selected from one declared archive or a whole-file operation, and its exact output SHA-256, byte count, regular-file type, and mode. Ordered OCI layers may each supply individually selected exact members, but Packet 3B does not claim OCI overlay or whiteout materialization. The transform vocabulary is closed to `archive_member` and `whole_file`; every concrete materializable artifact and every derived destination must be accounted for.

The lock fixes linux/amd64 and the Packet 3A runtime contract. Acquired artifacts are mode `0444`, single-link regular files with safe relative paths, exact bytes and SHA-256. OCI manifests/configs use their exact standard media types and are each capped at 1 MiB; layers may use the OCI uncompressed or gzip media type. Gzip means exactly one RFC 1952 member. The verifier validates its header/options, optional header CRC, DEFLATE stream, trailer CRC and size, rejects concatenated members, and rejects every trailing suffix byte including zero padding. The raw artifact SHA-256 therefore binds all accepted compressed bytes. Each config diff ID is recomputed from the corresponding uncompressed layer bytes. The compressed input plus expanded TAR is jointly capped at 512 MiB, rather than allowing two independent 512 MiB buffers. HTTPS authorities are the actual URL hostname and require no credentials, port, query, fragment, or mutable selector plus explicit version, date, or digest path evidence. The official dated Rust `dist/YYYY-MM-DD/rust-1.85.0-…` form is accepted. OCI authorities are the actual registry host and OCI locators bind the artifact digest.

Structural lock validation intentionally does not trust the lock's materializer declaration. Acquired-directory verification and materializer admission require a caller-provided exact materializer commit and source-tree SHA-256, and reject a missing or mismatched trusted join. Raw lock bytes—not reserialized JSON—provide the lock SHA-256 all the way to receipt verification.

The receipt verifier requires exact raw lock bytes, the acquired input directory, and trusted materializer context, and admits only a closed output graph: `runtime-manifest.json`, `rootfs.tar`, `layer.tar`, `config.json`, `manifest.json`, and `index.json`. It never trusts a separately supplied lock object. Before examining receipt outputs, it re-verifies every acquired artifact and derives every runtime mapping from the exact acquired bytes. A separate bounded input parser accepts ordinary POSIX ustar, GNU long-name, and PAX path records; validates checksums, numeric fields, body bounds, padding, terminators, and extension state; and rejects absolute, traversal, NUL, duplicate-resolved, malformed, sparse, or ambiguous members. Unselected directories, links, special entries, whiteout regular files, and metadata do not acquire overlay meaning; any mapped member must be an ordinary regular file with exact bytes. Whole-file mappings must equal their complete acquired blob. The runtime manifest must be the exact ordered projection of every lock mapping. Independently, the builder `rootfs.tar` and receipt output retain the stricter canonical tar parser and must contain exactly those mapped files plus that manifest, with exact directory/file metadata and content identities; the sole uncompressed OCI layer must have the same independently verified byte count and SHA-256 as `rootfs.tar`. The config diff ID, ordered manifest descriptors, sole index manifest/platform descriptor, final manifest-digest reference, and materializer/input-lock joins are then checked. A plausible receipt with substituted or self-consistent-but-unrelated output bytes is rejected. The lock bounds the planned closure to at most 64 artifacts, 4 OCI images, and 32,768 runtime mappings. Destinations have at most 12 components below `/opt/gate-h2`; the executable contract allows at most 32,768 unique canonical rootfs directories and 65,537 total canonical TAR entries, including the runtime manifest. These combined limits admit a shallow Packet 3A Rust, Node, native-tool, and Cargo-vendor closure without permitting an unbounded derived graph. The receipt has no free-form `source_commit`; its provenance is the trusted materializer identity. The two JSON Schemas are explicitly structure-only transport contracts; the executable validators are the sole semantic admission authorities, so schema validation is not claimed to have cross-field parity with executable validation. The focused tests exercise both layers separately against the same valid fixtures.

The verifier memory model targets an 8 GiB `t3a.large`. Raw input locks are capped at 32 MiB and receipt files at 1 MiB. The 1.5 GiB acquired cap is an on-disk aggregate, not an in-memory allocation: descriptor-anchored enumeration retains compact inode identities rather than every directory descriptor, then reopens each expected file through its verified root/current ancestor chain in deterministic path order. A second exact-tree snapshot and absolute-root identity rewalk reject membership, replacement, symlink, and race changes before admission. Secure-tree paths may have at most 16 parent directories; the verifier itself therefore holds at most 18 simultaneous descriptors for this operation (one retained tree root, 16 relative directories, and one file), independent of the number of wide sibling directories. Paths beyond that exact budget fail before traversal, and non-Linux full tree verification remains unsupported and fail-closed. An uncompressed artifact is capped at 512 MiB; for gzip, compressed plus expanded buffers are jointly capped at 512 MiB. Only parsed OCI manifest/config objects and compact layer diff IDs survive that pass. Receipt outputs are also visited sequentially. `layer.tar` is verified with a fixed 1 MiB digest buffer; `rootfs.tar` is the only large receipt buffer and is capped at 1 GiB, parsed once, and released before later outputs. Runtime/config/manifest/index metadata remain under their 16 MiB/1 MiB caps. Thus retained large buffers are bounded to one 512 MiB acquired working set or one 1 GiB rootfs, never the 1.5 GiB acquired aggregate and never simultaneous rootfs/layer buffers.

Acquired and receipt-output tree reads are Linux-only. Every absolute ancestor and tree directory is opened through retained descriptors under `/proc/self/fd`. Exact tree membership is established before processing; each expected file is then opened relative to its retained parent, processed, rebound, and closed before the next file. No-follow opens and before/opened/after checks bind device, inode, mode, size, link count, owner/group, mtime, and ctime, while final directory checks detect membership races. Non-Linux byte-tree verification fails closed with an explicit platform code; structure-only lock and receipt checks remain portable. The focused test runs the complete byte-tree and adversarial cases on Linux and covers the non-Linux stop boundary separately.

`materialize-builder-offline.mjs` validated the trusted join, acquired directory, and an empty owner-only output directory at the Packet 3B boundary, where it exited cleanly with `73` (`NOT_YET_MATERIALIZED`). Packet 3C replaces that historical deliberate stop with the synthetic/local materializer described in [the Packet 3C contract](gate-h2-builder-packet-3c-local-machinery-v1.md). Clearing `PATH` and proxy variables is only defense in depth; Packet 3C additionally requires external no-network execution for the full Linux verification boundary. Full receipt verification uses `--verify RECEIPT LOCK ACQUIRED OUTPUT COMMIT TREE`; structure-only receipt checking is intentionally weaker and must not be used for admission.

No lock instance, acquisition, image, receipt, external evidence, fixture update, commit, or deployment is produced by Packet 3B. Canonical assembly remains the explicit stop condition.
