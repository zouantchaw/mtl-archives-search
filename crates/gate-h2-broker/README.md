# Gate H2 HTTPS broker runtime

This crate contains the inactive issue #99 broker/runtime and the issue #100 host-side Podman supervisor for the merged issue #98 exact-exchange contract. It adds no destination manifest, provider credential, Cloudflare/D1/R2/prediction/publication authority, or real-Linux conformance claim.

## Implemented boundary

- `ProductionNetworkClient` resolves exactly once, rejects the complete answer set if any address is special-use, pins one allowed IPv4/IPv6 socket, verifies the connected peer, and performs exact-host rustls TLS 1.3 SNI/PKIX with byte-pinned native roots.
- Upstream HTTP/1.1 uses exact origin-form target, Host, fixed/auth/transport header order, one content length, identity encoding, connection close, monotonic connect/exchange budgets, streaming caps, and no proxy environment, redirect, retry, decompression, transfer encoding, or ambiguous trailing bytes.
- The launcher requires a detached Ed25519 authorization over the complete strict canonical launch config. `GATE_H2_ADMITTED_CODE_ID` embeds the reviewed code identity, while `GATE_H2_LAUNCH_AUTHORITY_TRUST_JSON` independently embeds the authority key, minimum sequence, and exact privileged replay-journal `dev`/`ino`/owner identity. The signed config supplies that already-open `O_RDWR|O_APPEND` journal FD; production rejects same-UID-owned or identity-mismatched journals. The broker pin is measured from the Linux kernel's running executable object, and the configured stage runtime is opened no-follow and retained after owner/type/single-link/`0555` mode/size/digest plus stable pre/post inode validation, so pathname replacement cannot substitute the checked object. Signing-key material is exactly 43 bytes of canonical unpadded base64url and must decode/re-encode exactly to one 32-byte Ed25519 seed. Request/handle cardinality, the exact credential-ID set, per-file bounds, checked aggregate bounds, and signed lengths are validated before any request or credential bytes are read. Normal builds carry no authority trust input.
- A fresh owner-only UDS authenticates the peer UID and exact one-use token/handle/order. Required request/response headers, safe-integer JSON, lengths, EOF, monotonic absolute read/write/accept deadlines, owner/mode/parent checks, and terminal failure sealing are enforced. Any evidence append/fsync fault before response delivery permanently closes the broker without releasing response bytes, and invalid or nonterminal lifecycles cannot be sealed. Before its terminal ACK, the stage validates the exact serialized response and retained role/hash/bytes/status joins and durably commits its receipt. That authenticated ACK additionally binds owner UID, token, manifest/capability/order, request ID, output index, and single-use state; only then can the broker seal complete. Its 204 is advisory, so losing it cannot reverse stage acceptance. Initial delivery or invalid/missing ACK replaces the pre-seal `response_committed` event with a durable valid failure. A nonterminal response-delivery failure retains the frozen behavior of consuming the next capability and sealing a failed lifecycle.
- The stage runtime validates every v2.2 field and schema pin, binds exact program bytes to a host authority, joins inputs/handles/capability IDs/output roles/statuses/indexes, and re-hashes the retained raw-response bytes before writing a receipt. Its production entrypoint accepts only connected inherited Unix-stream FDs at the fixed `3 + exchange ordinal` positions plus one terminal-ACK FD; it never validates one socket pathname and reconnects through another. Raw `.bin` outputs preserve exact arbitrary bytes, including zero bytes, newline endings, and empty bodies; the broker commits and hashes the exact retained output FD without reopening the authoritative member by pathname.
- Every consumed handle produces a valid v1 lifecycle ending in `response_committed` or `exchange_failed`. The unchanged v1 semantics and IDs are validated by the #98 TypeScript oracle. Runtime transcript files have one exact representation—JCS UTF-8 plus one LF—and the v2 envelope hashes those retained bytes. Validation rejects reformatting and joins the envelope signer ID and key to an exact, schema-pinned trust-entry artifact before checking Ed25519.
- Evidence and output directory creation validates an owner-controlled no-follow parent/directory, fixes mode `0700`, and fsyncs the parent before work can proceed. Parent-fsync failure is fail-sticky and cannot emit success/completion artifacts.

## Supervisor boundary

`gate-h2-post-begin-handoff` is the sole production-shaped SCM_RIGHTS path and the canonical combined relay/supervisor executable pin. Its fixed inherited inputs are canonical request bytes, the authorizer socket, and relay liveness; verifier trust is compiled from the source-pinned inactive enrollment, not supplied by an FD. A signed SCM_RIGHTS grant then carries, in fixed order, the supervisor config, handoff replay journal, empty report descriptor, canonical completion-expectation bytes, exact supervisor-config expectation bytes, one coordinator-retained run-root directory descriptor, and HTTPS broker descriptors. Before replay claim, target-FD installation, run-tree creation, spawn, or report mutation, the relay validates the complete received descriptor set in its transient SCM_RIGHTS form: cardinality, ordered target contract, regular-file/directory type, unique capability identity, sizes, hashes, seals, config/grant/expectation joins, and retained root identity. Authoritative config, completion, and report JSON use the shared `gate_h2_lexicographic_utf8_json_v1` compact recursive lexical-key algorithm, never Rust declaration order. The config and grant bind the root descriptor's role, order, FD target, path-for-diagnostics, device, inode, owner, group, mode, and link count. The supervisor consumes that FD directly for `mkdirat` and never re-opens the root pathname for authority. Only after complete validation does `RunLease` exclusively create the single-component child, and it can clean up only that child. HTTPS raw-response roles must exact-join their typed writable host paths, which are retained in broker evidence. The TypeScript failure-matrix fake is orchestration/D1 diagnostic-only and never creates or removes a run tree; native Rust descriptor tests are the sole evidence for descriptor-relative lifecycle authority. The supervisor snapshots every read-only source descriptor-relatively into its owned child, fsyncs and revalidates the copy, and mounts only snapshot FDs. It owns the write end of an internal liveness pipe and passes the fixed read end into the container; the stage runtime verifies that FIFO and exits on EOF, so an abrupt supervisor death also terminates the container workload. `ChildFdPlan` leaves only explicit target FDs open after exec. One absolute lifecycle deadline plus mandatory cleanup reserve bounds spawn, wait, TERM/KILL/reap, removal, walk, and cleanup. Issue #101 exclusively owns independent real-Linux/Podman conformance and admission; macOS tests and the cfg-gated harness do not substitute for that evidence.

The Packet 3A build entrypoint is a future Linux-only contract, not evidence of a completed build. It requires a reviewed digest-pinned builder image, trust roots, source descriptor, exact Git archive and bundle proof, and a retained staging receipt whose original descriptor SHA-256 is carried into both image verification and host admission. The image-owned verifier proves the descriptor's commit/tree/archive/exact Git blob and mode identities, rejects `.gitattributes`-transformed bytes, seals and remeasures a measured source snapshot, and builds both passes only from that snapshot. The image runtime closure is inventory-bound, root-owned, non-symlink `0755` directories with offline Cargo vendor/config and Git config, Rust/Cargo `1.85.0`, Node `22.22.0`, musl compiler/subtools/libc, CMake, Ninja, and static ELF64 little-endian x86-64 checks. Rootless Podman uses keep-id mapping, read-only inputs, confined writable locations, and a root proof supervisor restricted to `SETUID`, `SETGID`, and `SETPCAP` before dropping exactly to `65532:65532` with zero child capabilities.

Admission opens the candidate with `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, retains that FD, enumerates and opens the exact top-level set relative to it, and binds final inode identities before returning one checked snapshot. Artifact-specific caps are 64 B marker, 64 KiB provenance, 4 MiB SBOM, 32 MiB broker, 80 MiB rootfs, and 160 MiB OCI, with a 256 MiB aggregate cap. Marker/provenance/SBOM are validated before archives. One exact POSIX-ustar header representation is generated and accepted; every header byte, numeric/checksum encoding, type, terminator, data pad, and reserved byte is checked, while GNU/PAX/base-256/link/sparse/device alternatives are rejected. OCI layout/index/manifest/config descriptors, media types, digests, sizes, `amd64`/`linux`, `65532:65532`, entrypoint, diff ID, history, and layer/rootfs bytes join exactly. Every SBOM component matches the trusted expected bytes. Candidate, admitted, and published `gate-h2-broker` mode is `0555`; nonexecutables are `0444`.

Launch consumption uses one trust-pinned, privileged, pre-opened append journal FD. `flock` serializes processes; every complete record participates in high-water derivation; malformed, partial, oversized, replayed, or rolled-back state fails closed. Replacing or deleting its old pathname cannot change the retained journal identity. Publication consumes an admission descriptor containing exact member modes, sizes, and hashes, enforces artifact-specific and 256 MiB aggregate bounds, streams exactly each recorded size with overflow detection, `fchmod`s every staged artifact, and verifies source/staged/destination hashes and retained inodes. It rejects requested-parent or destination rebinding. Exact `EEXIST` plus an observed destination is the only conflict classification; other rename failures persist `rename_failed_unknown`. Success retains a durable identity-bound `published` state and emits the same receipt, so marker absence is never interpreted as success.

The admission/publication helpers have no default-build `GATE_H2_TEST_*` branches. Fault injection exists only behind the non-default `test-fault-injection` feature. Exactly two host helper families, `gate-h2-publish-noreplace` and `gate-h2-secure-candidate-read`, are independently rebuilt in both target trees and emit pass-1, pass-2, executable, and manifest digests; host code performs no helper compilation. It verifies all artifacts, unlinks executable helper paths on Linux, and executes only retained verified descriptors. The inner builder derives the expected SBOM from `cargo tree`; candidate metadata independently derives its SBOM from Cargo metadata, and exact disagreement fails. Admission and publication remain one process. Their fixed inherited interface carries one unlinked admission descriptor FD, one retained destination-parent directory FD, and six ordered unlinked admitted member FDs. Admission closes the candidate source-directory FD before returning that publication capability; publication never consumes a source pathname or source-directory capability. The descriptor hash appears in every durable publication state. The privileged journal and inherited connected stage channels are #100 supervisor implementation contracts; #101 supplies their dependent independent real-Linux proof. See [`gate-h2-builder-packet-3a-v1.md`](../../docs/dataset-factory/gate-h2-builder-packet-3a-v1.md).

Issue #101 must independently retain Linux evidence for `SO_PEERCRED`, sealed memfds, static linkage, sandbox flags, and byte-identical binary/rootfs/OCI outputs. That evidence is not claimed by this macOS change. Production remains inactive until an external authority admits the exact launcher config and all referenced pins.
